用 Kimi Code 核对财务分析报告的 Prompt

财务分析报告最怕的不是措辞不漂亮，而是表格算错、正文引用错、期间写错、结论和数据对不上。 这篇文章以 Kimi Code 为例，记录一个可复制的核对流程和 prompt。

2026.05.07 财务分析 / 效率工具 / Kimi Code 约 8 分钟阅读

适用场景

这个 prompt 适合用在非敏感、可外发或已脱敏的 Word 财务分析报告上。它不是替代人工复核，而是把第一轮机械性检查交给 AI Agent： 让它逐页、逐表、逐段找计算错误、表文不一致、期间错误、文字问题和逻辑跳跃。

我的使用习惯是：先让 Agent 输出结构化问题表，再由人工逐条判断是否采纳。财务报告里很多问题不是“有没有错”这么简单， 而是需要结合底稿、口径和业务背景判断，所以 prompt 里特意保留了“需进一步核实”的出口。

安装 Kimi Code

Kimi Code CLI 是 Moonshot AI 提供的本地 Agent 工具。根据 官方快速开始文档， Windows PowerShell 可以用下面的命令安装： 

Invoke-RestMethod https://code.kimi.com/install.ps1 | Invoke-Expression

安装完成后，检查版本：

kimi --version

第一次使用时，在项目目录中运行 `kimi`，然后输入 `/login`。官方文档建议选择 Kimi Code 平台完成浏览器 OAuth 授权； 如果选择其他平台，则需要配置对应的 API Key。 

cd your-project
kimi

/login

使用 Kimi Web

如果不想一直在终端里对话，可以启动 Kimi Code 的 Web UI。根据 官方 Web UI 文档， 在终端执行： 

kimi web

服务启动后会自动打开浏览器，默认地址是 `http://127.0.0.1:5494`。如果端口被占用，Kimi 会尝试后续可用端口并在终端里打印访问地址。 如果需要指定端口，可以使用： 

kimi web --port 5495

如果要让局域网内其他设备访问，可以用 `--network` 绑定到 `0.0.0.0`。这类用法要注意网络环境和文件权限，财务报告尤其不要放在不可信网络中操作。 

kimi web --network --port 5494

使用方法

  1. 新建一个临时工作目录，只放本次要核对的 Word 报告和必要的非敏感附件。
  2. 在该目录运行 `kimi web`，打开浏览器界面。
  3. 上传或引用 Word 报告文件，把下面的 prompt 粘贴给 Kimi Code。
  4. 等待它输出 Markdown 核对结果后，逐条人工复核。
  5. 对“高风险”“需进一步核实”的问题，回到底稿、报表或原始数据中确认。

这段 prompt 的重点是“逼迫模型具体化”：不要只总结，要给位置、原文、核对发现、建议修改和风险等级。 对财务报告而言，可复核的结构化输出比漂亮的长段总结更重要。

Prompt

你是一名严谨、细致的财务分析与审阅专业人员。请对我提供的 Word 财务分析报告进行全面核对，重点关注数据准确性、表文一致性、分析逻辑、文字质量及报告期间是否正确。请逐页、逐表、逐段进行检查，不要只做概括性审阅。

## 一、核对目标

请从以下方面对报告进行完整核对：

### 1. 表格数据准确性核对

请逐一核对报告中每一个表格的数据，至少包括：

- 横向计算是否准确；
- 纵向计算是否准确；
- 合计数、小计数是否正确；
- 比例、占比、结构比是否正确；
- 增减额是否正确；
- 增减幅度、增长率、下降率是否正确；
- 平均数、单位换算、万元/元/亿元等金额单位是否一致；
- 百分比、小数位、四舍五入是否合理；
- 表内同一指标在不同位置重复出现时，数值是否一致；
- 表头、列名、行名与数据内容是否匹配。

如发现计算错误，请列明原表数据、报告披露结果、重新计算结果及差异。

### 2. 表格与文字描述的一致性核对

请核对正文文字中引用的所有财务数据是否与表格一致，包括但不限于：

- 正文引用金额是否与表格一致；
- 正文引用比例、增减额、增减幅度是否与表格一致；
- 正文描述的增减方向是否与表格一致，例如“增加”“下降”“增长”“减少”等；
- 正文描述的主要原因是否与数据变化方向、变化幅度相匹配；
- 正文提到的排名、占比、结构变化、主要项目等是否与表格数据一致；
- 同一数据在摘要、正文、表格、结论等不同位置是否一致。

如发现不一致，请指出正文位置、对应表格位置、不一致内容及建议修改表述。

### 3. 分析内容合理性核对

请从财务分析专业角度判断报告中的分析是否合理，包括：

- 分析结论是否由数据支持；
- 是否存在数据变化较小但文字过度解读的情况；
- 是否存在数据变化较大但未充分说明原因的情况；
- 是否存在因果关系牵强、逻辑跳跃或结论依据不足的情况；
- 是否存在指标口径混用，例如营业收入、主营业务收入、利润总额、净利润、归母净利润等混淆；
- 是否存在资产负债表、利润表、现金流量表项目之间勾稽关系异常；
- 是否存在同比、环比、期初期末、预算完成率等分析口径混用；
- 是否存在将“金额增加”误写为“占比增加”或反之的情况；
- 是否存在将绝对值变化与相对比例变化混淆的情况。

请对不合理或依据不足的分析提出更稳妥、专业的修改建议。

### 4. 文字质量核对

请逐段检查报告文字表述，重点包括：

- 是否存在错别字；
- 是否存在语病；
- 是否存在重复、遗漏、前后矛盾；
- 是否存在标点符号错误；
- 是否存在单位遗漏或单位错误；
- 是否存在财务术语使用不准确；
- 是否存在表述不够正式、不适合财务分析报告的措辞；
- 是否存在主语不明、指代不清、逻辑衔接不顺；
- 是否存在“增加/增长”“减少/下降”“提升/提高”等词语使用不准确。

请给出具体修改建议，不要只写“存在语病”。

### 5. 报告期间一致性核对

请重点核对报告内容归属期间是否统一为“2025年度”。检查范围包括但不限于：

- 报告标题；
- 页眉、页脚；
- 目录；
- 各级标题；
- 表格标题；
- 表头、表内文字；
- 正文描述；
- 注释、脚注；
- 附件或附表；
- 结论部分。

请检查是否存在误写为其他年度、其他期间或期间表述不一致的情况，例如“2024年度”“2023年度”“本期/上期”对应关系错误等。

### 6. 格式与展示问题核对

请同时关注以下格式问题：

- 表格编号是否连续；
- 图表标题是否准确；
- 表格与正文引用关系是否清楚；
- 金额单位是否统一；
- 小数位数是否统一；
- 负数、括号、百分号、千分位格式是否统一；
- 表格列宽、换行、对齐是否影响阅读；
- 是否存在空白表格、残留批注、修订痕迹、占位符或未删除的模板文字。

## 二、核对方法要求

请按照以下方法进行核对：

1. 不要只抽查，应尽可能覆盖报告全文、全部表格和全部关键数据。
2. 涉及计算的地方，请自行重新计算，不要直接相信报告中的结果。
3. 涉及文字引用数据的地方，请回到对应表格进行勾稽。
4. 对于无法判断或缺少底稿支持的事项，请明确标注为“需进一步核实”，不要武断判断。
5. 如果发现疑似问题但不确定，请说明判断依据和不确定原因。
6. 对每一项问题，请尽量给出可直接替换进报告的修改建议。

## 三、输出要求

请将核对结果整理为 Markdown 文件，并保存为：

`财务分析报告核对结果.md`

Markdown 文件内容请按以下结构输出：

# 财务分析报告核对结果

## 一、总体核对结论

请简要说明：
- 是否发现重大数据错误；
- 是否发现表文不一致；
- 是否发现期间错误；
- 是否发现明显文字或逻辑问题；
- 报告整体是否建议修改后再使用。

## 二、问题明细表

请用 Markdown 表格列示所有发现的问题，表格字段包括：

| 序号 | 问题类型 | 所在位置 | 原文/原数据 | 核对发现 | 建议修改 | 风险等级 |
|---|---|---|---|---|---|---|

其中：
- “问题类型”可包括：计算错误、表文不一致、期间错误、分析逻辑问题、文字表述问题、格式问题、需进一步核实等；
- “所在位置”请尽量写明页码、章节、表格名称、段落或标题；
- “原文/原数据”请摘录存在问题的内容；
- “核对发现”请说明具体问题；
- “建议修改”请给出明确修改意见；
- “风险等级”分为：高、中、低。

## 三、表格计算核对明细

请单独列示涉及表格计算错误或疑似错误的问题，包括：

| 表格名称 | 指标/行列 | 报告披露数 | 重新计算数 | 差异 | 说明 |
|---|---|---:|---:|---:|---|

## 四、表文一致性核对明细

请单独列示正文引用数据与表格不一致的问题，包括：

| 正文位置 | 正文引用内容 | 对应表格数据 | 是否一致 | 建议修改 |
|---|---|---|---|---|

## 五、期间一致性核对明细

请列示所有涉及非“2025年度”或期间表述不清的问题，包括：

| 所在位置 | 原期间表述 | 问题说明 | 建议修改 |
|---|---|---|---|

## 六、文字及表达优化建议

请列示错别字、语病、表达不准确、财务术语不规范等问题，并给出建议修改稿。

## 七、需进一步核实事项

请列示因缺少底稿、源数据、上下文或外部依据而无法最终判断的事项。

## 八、最终修改建议摘要

请按重要性归纳最需要优先修改的问题，区分：
- 必须修改；
- 建议修改；
- 可优化。

## 四、注意事项

- 请保持专业、审慎、客观。
- 不要遗漏小数位、单位、方向性描述等细节问题。
- 不要只输出总结，必须输出具体问题明细。
- 如果未发现某类问题，也请明确写明“未发现明显问题”。
- 最终请保存 Markdown 文件，并确保文件内容完整、结构清晰、便于后续人工复核。

几个使用提醒

  • 不要上传未脱敏或不适合外部工具处理的财务资料。
  • 如果报告里有大量表格，建议同时提供 Excel 底稿，便于模型核算。
  • AI 输出的问题表是“复核线索”，最终结论仍应由人确认。
  • 如果报告期间不是 2025 年度，记得把 prompt 里的期间要求改掉。
