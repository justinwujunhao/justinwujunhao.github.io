Hermes Agent / RAG / Accounting Standards

Hermes Agent + 飞书知识库构建个人会计准则问答库

这篇记录的是我用 Hermes Agent 搭建财会知识库的一次实践：不是把资料简单存起来，而是用 RAG 思路让准则原文、专题资料和真实问答可以被持续检索、引用和迭代。

2026.05.07 Hermes Agent / RAG / 会计准则 约 7 分钟阅读

为什么要搭这个知识库

我最初想解决的不是“把资料存起来”这么简单，而是让会计准则、监管规则和日常分析中反复遇到的问题，能够被长期沉淀、随时检索、准确引用。 财会资料的难点在于来源分散、条文很长、版本更新频繁，而且很多问题需要跨准则体系比较。

如果只是把 PDF 或网页收藏起来，真正使用时仍然要重新搜索、重新定位、重新判断。所以这个知识库的定位，是一个面向个人工作的财会第二大脑： 平时负责收集和整理原文，需要时辅助我快速回答“某条准则怎么规定”“新旧版本有什么变化”“PRC GAAP、IFRS、US GAAP 对同一问题有什么差异”。

Hermes Agent 在这里承担的角色，更像一个持续维护知识库的助手，而不是一次性问答工具。

整体框架逻辑

我把这个系统拆成四层：资料来源层、整理加工层、知识库结构层和应用场景层。这样做的好处是，每一次新增资料或新增问题，都能放回固定流程里处理，而不是临时拼凑。

  • 资料来源层：收集会计准则、解释公告、监管规则、交易所规则等原始资料。
  • 整理加工层：由 Hermes Agent 协助提取正文、整理标题层级、拆分条文、清理格式。
  • 知识库结构层：按准则体系、主题和对比文章组织飞书知识库目录。
  • 应用场景层：支持原文查询、三准则对照、版本更新、专题复盘和定期巡检。

使用 Hermes Agent 的整体流程

目前我比较认可的流程，是先建结构，再入库资料，最后用真实问题反复验证。

  1. 明确知识库边界：先聚焦会计准则、法规规则和高频财务分析问题，不急着把所有资料都塞进去。
  2. 确定目录结构：将 PRC GAAP、IFRS、US GAAP、监管法规、交易所规则和专题对比文章分层管理。
  3. 整理原始资料：让 Hermes Agent 协助从网页、PDF、Word 或 Markdown 中提取正文，清理无关格式和噪声。
  4. 写入飞书知识库：长内容优先沉淀为知识库文档，而不是通过聊天消息分段发送，保证后续可阅读和可复用。
  5. 用问题验证质量：每次入库后，用具体问题测试能否找到原文、引用位置是否准确、回答是否有依据。
  6. 定期巡检更新：对目录、重复条目、重点准则和新增资料进行检查，避免知识库只建不管。

目录结构的设计原则

这个知识库最容易出问题的地方不是技术，而是目录结构。财会知识有天然的体系差异，如果一开始目录关系放错，后续检索和对比都会很别扭。

  • 准则原文和分析文章分开：原文用于引用，分析文章用于解释和对比，不能混在一起。
  • 不同准则体系并列：IFRS、PRC GAAP、US GAAP 是并列体系，不应把 IFRS 放在中国准则下面。
  • 对比文章挂在对应主题下：例如收入、长期股权投资、金融工具等专题，可以在原文节点下放对比分析文档。
  • 监管规则单独成区：交易所规则、监管问答和上市公司规则更适合按机构和主题组织。
  • 保留人工修正空间：Agent 可以帮助整理，但准则知识库必须允许人工调整标题、归类和说明。

一个会计准则查询案例：RAG 闭环如何跑通

这里更适合用一个完整查询案例来说明，而不是只列举已经入库了哪些资料。这个知识库本质上采用的是 RAG 思路： 先把可信准则、法规和专题资料沉淀到知识库中，用户提问时先检索相关内容，再让 Agent 基于检索结果组织回答。重点是先找依据，再生成回复。

案例问题：某项交易应当如何判断是否适用权益法？IFRS 和中国准则在处理思路上是否有差异？

1. 提出问题

用户先提出一个具体会计问题。这个问题不要求用户自己知道准则编号，也不要求提前判断属于哪个准则体系。 Agent 需要做的第一步，是把自然语言问题转换成可检索的关键词和主题，例如“权益法”“长期股权投资”“重大影响”“IFRS”“PRC GAAP”等。

2. 知识库搜索

Hermes Agent 先到飞书知识库中检索相关资料，而不是直接凭模型记忆回答。检索对象可以包括准则原文、解释公告、专题对比文章和历史问答沉淀。 这里的 RAG 逻辑很关键：知识库负责提供可信上下文，Agent 负责理解问题、筛选材料并整理表达。

3. 命中资料时：整理依据并回复

如果知识库中能找到相关内容，Agent 应先列明参考到的准则或知识库文档，再整理回答。比较理想的回复结构是： 先给结论，再列出原文依据，随后说明适用条件、与其他准则体系的差异，以及仍需结合交易事实判断的事项。

例如，若知识库中已经有 CAS 长期股权投资、IAS 28 或相关专题文章，Agent 可以基于这些材料说明权益法适用的一般判断框架， 并指出不同准则体系下需要关注的口径差异。这样的回答不是“模型印象”，而是基于已入库资料的再组织。

4. 未命中资料时：明确回复没有相应知识

如果知识库没有找到足够材料，Agent 不应该强行编造。更好的回复是明确说明：当前知识库中未检索到足以回答该问题的准则原文或专题资料， 因此暂不能给出确定结论。这个“找不到就说找不到”的机制，是财会知识库最重要的安全边界之一。

5. 提示增补知识库内容

在未命中时，Agent 可以继续提示应该补充哪些材料，例如对应的准则原文、解释公告、监管问答、企业案例或已有研究笔记。 这样一次失败的查询，也会变成知识库建设的待办清单。

6. 增补后重新回复

当相关资料被补充进知识库后，Agent 再次检索并重新回答同一个问题。这个时候，回答就可以从“当前知识库暂无依据” 升级为“基于新补充资料的结构化答复”。这形成了一个闭环：提出问题、检索知识库、命中则回答、未命中则提示补库、补库后重新回答。

这个闭环的意义在于，知识库会随着真实问题不断变厚。每一次没有回答好的问题，都不是失败，而是在提醒我： 这里需要补充原文、专题文章或案例说明。

我对这个系统的使用边界

这个知识库可以提高检索和整理效率，但不能替代专业判断。尤其是会计准则适用问题，仍然需要结合交易实质、公司口径、审计判断和监管环境。 我的定位是：让 Agent 帮我更快找到依据、更清楚地组织材料，但最终结论仍由人负责。

  • 可以用于：原文检索、条文定位、准则差异初步比较、专题资料整理、学习复盘。
  • 谨慎用于：复杂交易判断、重大会计政策选择、审计争议事项、需要外部专业意见的问题。
  • 不应使用：让 Agent 在没有原文依据时直接编造准则结论。

下一步迭代方向

后续我希望把这个知识库从“资料仓库”继续推进到“工作台”。也就是说，它不只是放资料，而是能围绕真实工作问题持续更新。

  • 补充更多准则主题：优先覆盖收入、金融工具、长期股权投资、租赁、企业合并等高频主题。
  • 建立专题对比模板：每个专题都按“原文依据、主要差异、适用提醒、待核实问题”组织。
  • 强化来源标注：回答中尽量保留准则名称、章节、条文编号和知识库链接。
  • 增加更新日志：每次新增或修订资料，都记录来源、日期、处理人和适用范围。
  • 形成问答沉淀：把高质量问答整理回知识库，让一次提问变成长期资产。

阶段性总结

这次实践让我最大的感受是：AI Agent 真正有用的地方，不只是回答问题，而是帮助建立一个可持续维护的知识系统。 对于财会知识来说，最重要的不是生成一段看起来专业的话，而是能不能回到原文、能不能说明依据、能不能在下次遇到类似问题时复用。

Hermes Agent 搭建飞书知识库的价值，正是在于把散落的准则、法规和分析经验逐步沉淀成可查询、可对比、可迭代的个人知识资产。 当前系统还在早期阶段，但框架已经跑通，接下来值得继续做的是扩充内容、优化目录和沉淀更多真实案例。
